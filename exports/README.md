# Niger Drought AA — IRI trigger historical export

Raw historical IRI forecast / ENACTS observation data and the backtested trigger
record for the Niger drought anticipatory action trigger. Generated by
`exploration/export_trigger_data.py`.

**Authoritative deployment:** <https://ocha-dap.github.io/ds-aa-ner-drought/>
(interactive marimo explorer; the figures below are at its **default** sliders —
Forecast 35 %, Observational 15 % — which is what loads).

**Status:** DRAFT — not for distribution
**Design source:** `exploration/rolling_threshold_marimo.py`
**Data source:** IRI Maproom export, 25 April 2026, OCHA Certification model, 35 % frequency
**Evaluation period:** 2001–2025 (first year with a full 10-year rolling reference window)
**Target combined return period:** ≈ 3.5 years

---

## Trigger design

A year triggers if **either** arm fires (logical OR):

- **Forecast arm** — IRI below-normal probability for each of Jan–Jun. A month "fires"
  when its probability is in the **top 35 %** of its **rolling 10-year** reference window
  (threshold locked to the *k*-th highest actual value, `k = ceil(0.35 × 10) = 4`). The
  arm fires when **any two consecutive months** (Jan+Feb, Feb+Mar, …, May+Jun) both fire.
- **Observation arm** — ENACTS Jun–Jul SPI (column `Aug`). Fires when the value is in the
  **bottom 15 %** of the **full historical record** (`k = ceil(0.15 × 35) = 6`; single
  fixed threshold = −0.484, not rolling).

### Windows

| window | column | components |
|---|---|---|
| Window 1 (Jan/Feb/Mar forecast) | `ner_drought_v1_wt1` | pairs Jan+Feb, Feb+Mar, Mar+Apr |
| Window 2 (Apr/May/Jun forecast **or** Aug obs) | `ner_drought_v1_wt2` | pairs Apr+May, May+Jun, **or** the observation arm |

The **Mar+Apr** pair straddles the two windows and is assigned to Window 1 so that
`wt1 OR wt2` exactly reconstructs the authoritative either-arm record. In this dataset
Mar+Apr only fires in 2001, which already triggers Window 1 via Jan+Feb and Feb+Mar, so
the assignment has no effect on the result.

## Files

### `trigger_history.csv` (25 rows, 2001–2025)

Annual backtested trigger record.

| Column | Description |
|---|---|
| `year` | Season year |
| `jan_feb` … `may_jun` | 1 if both months of that consecutive forecast pair fired |
| `forecast_arm` | 1 if any consecutive pair fired |
| `obs_arm` | 1 if Aug SPI ≤ obs threshold |
| `aug_spi` | ENACTS Jun–Jul SPI value (the observation-arm metric; lower = drier) |
| `obs_threshold` | Fixed observation threshold (−0.484) |
| `ner_drought_v1_wt1` | Window 1 flag (Jan+Feb / Feb+Mar / Mar+Apr) |
| `ner_drought_v1_wt2` | Window 2 flag (Apr+May / May+Jun / obs arm) |
| `either` | `wt1 OR wt2` — the combined trigger (authoritative activation record) |

### `forecast_month_thresholds.csv` (150 rows)

Per year × month forecast-arm detail.

| Column | Description |
|---|---|
| `year`, `month` | Evaluation year and forecast month (Jan–Jun) |
| `rolling_threshold` | Top-35 % threshold from the rolling 10-yr window (% below-normal) |
| `actual_prob` | Actual IRI below-normal probability that month (%) |
| `triggered` | `actual_prob ≥ rolling_threshold` |

### `iri_maproom_raw.csv` (35 rows, 1991–2025)

The raw IRI Maproom export — the authoritative input, unmodified.

| Column | Description |
|---|---|
| `year` | Year |
| `Jan` … `Jun` | IRI below-normal probability (%) by forecast issue month |
| `Aug` | ENACTS Jun–Jul SPI (observation-arm metric, labelled `Aug`) |
| `JAS_SPI` | Jul–Aug–Sep SPI (reference, not used by the trigger) |

- **Source blob:** `ds-aa-ner-drought/raw/iri/ner_maproom_export_2026-04-25_thresh35 - Sheet1.csv`
- Note: 1991–2000 are used only to seed the rolling reference window; the trigger is
  evaluated 2001–2025.

## Notes

- **Higher forecast value = drier** — `Jan`–`Jun` are probabilities of *below-normal*
  rainfall, so the forecast arm fires on **high** values (top of the window).
- **Lower `Aug` = drier** — the observation arm fires on **low** SPI (bottom of the record).
- The threshold percentile convention locks to actual observed values (`k = ceil(p × n)`),
  so no interpolation is used; see the deployed app and `rolling_threshold_marimo.py`.
- This is a **draft** design (rolling-window methodology on the `iri-trend` branch). A
  parallel detrended design lives in `index.qmd`; the deployed default here is the
  rolling-window marimo app.
